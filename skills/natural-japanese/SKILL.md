# natural-japanese

仕事の日本語文書を、読みやすく自然な日本語で書く・直すためのスキル。

## 考え方

- **見つけるのはモデル、決めるのはあなた。** 生成AIは、自分の書く言い回しの癖に気づけない。LLM に「この語は自然か」と聞いても、生成AI時代の言い回しは不自然と判定されない。だから見つけるのは、生成AI以前の日本語で学んだモデル(`scripts/style_check.py`)に任せる。直すかどうか、どう言い換えるかは、あなたが文脈で決める。
- **意味を変えない。** この種の言い回しは、読み手が意味を取れなくなる問題ではない。直すときは意味を保つことを最優先にする。具体的な事実や数値を足して直すと、かえって意味がずれる。
- **推敲で増やさない。** 推敲すると、原文になかった言い回しが入りやすい(「大きく影響する」が「大きく効く」になる)。直した後は原文と比べる。
- **指摘と直し方を残す。** 出すのは直した文書だけではない。どこを、どう直したか、直さなかったならなぜかの一覧も添える。

## 対象

| 文書 | 型 |
|---|---|
| 調査・分析レポート | `references/doctypes/report.md` |
| 議事録 | `references/doctypes/minutes.md` |
| 社内ガイド・マニュアル | `references/doctypes/guide.md` |
| PR の説明文 | 型なし(文体の決まりだけで書く) |
| 技術記事 | 型なし(文体の決まりだけで書く) |

ほかの文書(note、エッセイ、スライドなど)でも、文体の決まりと言い回しの検査は使える。

## 手順

### 1. 読者と型を決める

誰が読み、読んだ後に何をしてほしいかを決める。わからなければユーザーに聞く。型のある文書なら、上の表のファイルを読む。新しく書くときは、書く前に主メッセージを一文で書く。書けないなら、足りないのは書き方ではなく材料だ。

### 2. 書く・直す

`references/writing-constitution.md` の決まりに沿って書く。既存の文書を直すときは、直す前のファイルの写しを一時ディレクトリ(`/tmp` など)に置いておく(手順5で使う)。手順4の `items.json` も同じ場所に置き、作業が終わったら消す。ユーザーのプロジェクトに残すのは、直した文書だけにする。

### 3. 言い回しを調べる

```
uv run scripts/style_check.py flag <file> --json
```

生成AI以前の書き手ならその位置に置かなかったはずの語を、文ごとに示す。数字(差)が大きいほど、生成AI時代の文章に偏った語だ。カタカナ語・英字の語・固有名詞・数詞は調べない。初回はモデル(約420MB)をダウンロードする。CPU で動き、本文1,000字あたり1秒ほどかかる。

### 4. 指摘ごとに決める

示された文ごとに、次のどちらかを決める。詳しい判断の仕方と例は `references/ai-era-phrasing.md` にある。

- **変えない**: 文字どおりの意味で使っている(「配信が止まる」)、題材の用語や固有の呼び名である(「型推論」)、ふつうの言い方である(「ブラウザ拡張を作る」)。迷ったら変えない
- **言い換える**: 示された語とその前後だけを書き換えた文を3つまで作る。意味と確信の度合いを変えず、文脈にない事実を足さない

言い換えるときは、候補をモデルに並べさせる。

```
uv run scripts/style_check.py rank items.json
# items.json: [{"id": "L12", "sentence": "元の文", "candidates": ["候補1", "候補2"]}]
```

`chosen` が、生成AI以前の書き手が書きそうな順の1番目だ。基本はこれを使う。ただし `chosen` が元の文と意味の違う文になっていたら、意味を保っている次の候補を使う。モデルは自然さしか見ておらず、意味は見ていない。

### 5. 原文と比べる(既存の文書を直したとき)

```
uv run scripts/style_check.py compare <直す前のファイル> <直した後のファイル>
```

原文になかった生成AI時代の語が出たら、0 になるまで直す。第一候補は、原文の言い方に戻すことだ。新しく書いた文書では、仕上げた文書にもう一度 `flag` をかけ、手順4で「変えない」と決めた語以外が残っていないかを見る。

### 6. ほかの機械の検査を1回

```
uv run scripts/lint.py <file>
uv run scripts/lint.py --reading-load <file>
```

対応するのは次の3つだけでよい。ほかの項目は、このスキルでは使わない。

- `forbidden_phrase`: 「重要なのは」「ポイントは」のような、生成AIに多い決まり文句
- `antithesis_repetition`: 「〜ではなく〜」の繰り返し
- `sentence_too_long`(`--reading-load`): 長すぎる文。一文一義に分けられないかを見る

### 7. 一覧を添える

直した文書と一緒に、次の一覧を返答の中に添える。

| 行 | 元の文 | 直した文 | 理由 |
|---|---|---|---|
| L12 | 設定が後から効いてくる。 | 設定の影響が後から出てくる。 | 「効く」は生成AI時代に増えた言い方。意味は同じ |
| L20 | 次回はブラウザ拡張を作ってみたい。 | (変えない) | 「作る」はふつうの言い方 |

モデルが示さなかった箇所を、文体の決まり(手順2)に沿って直したときも、同じ一覧に載せる。

## uv が使えない環境

モデルが動かせないときは、`references/ai-era-phrasing.md` の例を見ながら自分で読み直す。ただし、生成AIは自分の言い回しの癖に気づけないので、見落としが多いことをユーザーに伝える。
