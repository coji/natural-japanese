# 参考にした枠組み:論点思考とロジカル・プレゼンテーション

このスキルの問いの型は、次の2冊から借りている。言い回しは借りず、考え方だけを使う。ここに書くのは2冊の要点を作者の言葉で言い直したもので、原文の引用ではない。改善を考えるときは、まずこの枠組みに照らして「どの型の問いが足りないか」を見る。

- 内田和成『論点思考 BCG流 問題設定の技術』(東洋経済新報社、2010)
- 高田貴久『ロジカル・プレゼンテーション 自分の考えを効果的に伝える戦略コンサルタントの「提案の技術」』(英治出版、2004)

## 1. 論点思考(内田)の要点

問題解決の最初の工程は、解くことではなく、解くべき問いを選ぶことである。

1. 論点とは「解くべき問題」。間違った論点を解けば、どれだけ上手に解いても成果は出ない。正しい答えより正しい問いが先にある
2. 現象は論点ではない。「売上が落ちている」「残業が多い」は観察した事実で、論点は「なぜ落ちたか」「何をすれば減るか」のように、答えると次の行動が決まる形をしている。現象を論点として扱うと、対策が現象の裏返しになる
3. 論点は立場で変わる。同じ文書でも、起案者の論点(この施策を通したい)、決裁者の論点(この投資は見合うか、ほかに手はないか)、実行する人の論点(自分の仕事は増えるか)は違う。文書は決裁者の論点に答えていなければならない
4. 論点には階層がある。最後に答えるべき問い(大論点)の下に、答えるために要る問い(中論点・小論点)が並ぶ。大論点が決まらないまま小論点を解くのが、いちばん多いむだ
5. 候補を広げてから、当たりをつけて絞る。全部を網羅的に調べない。筋のよい論点は、解けば効果が大きい、実際に解ける、短い時間で答えが出る、の3つを満たす
6. 論点は確かめるもの。本当の論点は、依頼した人の頭の中にあって、依頼文には書かれていないことが多い。質問を重ねる、仮説をぶつけて反応を見る、上位の目的から考える、反対の立場から考える、で引き出す

## 2. ロジカル・プレゼンテーション(高田)の要点

提案を通すのに要る力を4つに分け、順に積む。

1. 論理思考力。筋が通っているとは、縦と横の2方向で成り立つこと
   - 縦の論理(本当にそうか):主張と根拠が因果でつながっているか。読み手が「なぜそう言えるのか」と聞いたとき、根拠が答えになっているか。飛躍の原因は3つ。前提条件のちがい(書き手と読み手で前提が違う)、異質なものの同質化(違うものを同じ扱いで並べる)、偶然の必然化(1回の出来事を一般化する)
   - 横の論理(それだけか):並べた項目に漏れとダブりがないか。通らない原因は、言葉のレベル感がそろっていない、切り口がずれている、抜けている、の3つ
2. 仮説検証力。目的を理解し、相手の論点を理解し、仮説を立て、検証し、示唆を出す。この順序を守る。論点を外した検証は、どれだけ精密でも役に立たない
3. 会議設計力。その場で何を決めてもらうのか、誰がどの立場で出席するのか、落としどころはどこかを、資料より先に決める。決める場の設計が、資料の形を決める
4. 資料作成力。論点、結論、根拠の順に置く。1つの単位に1つのメッセージ。受け手が決めるのに要る材料だけを本編に置き、裏づけは別に添える

## 3. このスキルでの使い方

| 枠組み | スキルのどこに当たるか |
|---|---|
| 縦の論理、飛躍の3原因 | logic の「矛盾」「根拠のない主張」(前提条件のちがい・異質なものの同質化・偶然の必然化の小分類)、「事実と推論の混在」 |
| 横の論理 | logic の「横の論理(並列の漏れ・ダブり・ねじれ)」 |
| 論点は立場で変わる、現象は論点ではない | somosomo の「問いそのもの」(文書が答えている問いと、決裁者が決めたいことが同じか) |
| 論点は確かめるもの、前提の違い | somosomo の「前提」。書き手が当たり前と思っていて読み手が共有していない前提 |
| 候補を広げる | somosomo の「他の選択肢」(何もしない・やめる・自前で・範囲を変える、の型だけを名指しする) |
| 仮説検証(覆る条件) | somosomo の「覆る条件」 |
| 会議設計(誰が決め、誰がやるか) | somosomo の「利害と実行」。組み直しの「頼む中身を小さくする案」(決める場と決裁の範囲を設計し直す) |
| 資料作成(論点→結論→根拠、本編と裏づけの分離) | 「直す」の本編と付録の切り分け、「組み直す」の先頭に置く理由の選び直し |

## 4. 枠組みに照らして、まだ足りないもの

改善を考えるときの出発点。どれも「問いの型が足りない」か「問いの扱いが足りない」のどちらか。

1. (CT1 で対応。somosomo に「決裁者の論点」と「決裁事項を倒しうる問い」を足した)論点の階層を扱っていない。somosomo は問いを5つの型で並べるが、「決裁者の大論点は何か」を1つ決めてから、各問いがその大論点にどう効くかを書いていない。確認事項が20件並ぶのは、小論点を平らに並べているからで、論点思考なら「大論点を倒しうる問い」から順に3つほどに絞る
2. 筋のよい論点で絞っていない。効果が大きい・答えが出せる・短時間で答えられる、の3つで問いを選別していない。「手元の材料で確かめられる」の問いを足したのは、この「短時間で答えが出る」の一部
3. (CT2 で一部対応。一括経路で「決めてもらうのは X と読んだ。違うか」を3つの問いの1つとして聞く)論点を確かめる手段が「問いを返す」だけ。論点思考は、仮説をぶつけて反応を見る、上位の目的から考える、を勧めている。スキルは「書き手の代わりに決めない」が、「この文書の大論点は X だと読んだ。違うか」と1つだけ仮説をぶつける手は、決めることとは違う
4. (CT1 で一部対応。「決裁者の論点」の1行で、誰が何を決める文書かを検査の最初に書く)会議設計の視点が組み直しにしか入っていない。「この文書で、誰が、何を、いつ決めるのか」は検査の最初に確かめるべきことで、logic の「文書の性格」の1行では足りない
5. 資料作成の「1単位1メッセージ」を検査していない。見出しがその節の結論を言っているか、段落の先頭文が主張かは、natural-japanese の領分として残している
