# 構成案:ミナトノート試験導入の稟議書(doc-review.md の組み直し)

行番号は doc-review.md の行番号です。L と S の番号は report-logic.md と report-somosomo.md の指摘を指します。この2つの報告は doc.md を検査したものなので、問いのうち doc-review.md で答えが出たものは、各案の中でそう書きました。どの案も、doc-review.md にある事実と頼む中身だけで作っています。

答えが出た問いは3つです。週8件は部全体の件数(行22)、時間単価は3,500円(行33)、6か月で解約できる(行62)。答えが出ていない問いのうち、決裁事項を倒しうるのは次の3つです。部全体の平均作成時間(行25)、データの扱いが社内規程に合うか(行53)、顧客の同意の割合(行41、行73)。

書いた本文は案2です。案1は頼む中身そのものが変わるので、書き手にしか選べません。

## 案1 頼む中身を小さくする案(測ってから頼む)

**主張**:12名・6か月・上限60万円の承認は今回求めず、2週間の作成時間の測定と、データの扱いと社内規程の突き合わせを先に済ませ、結果を見てから頼む。

**縮めた決裁事項**:今回の決裁事項はなし。結果を見てから、次の2つを頼むかどうかを決める。

1. 「ミナトノート」を営業部の営業担当12名で6か月間試験導入すること
2. 費用の上限を月額10万円、6か月合計60万円とすること

**先に置くこと**:部全体の平均作成時間の測定(2週間あれば12名分を記録でき、承認の前に測ることもできる。行25)、ミナトノートのデータの扱いの資料の取り寄せと社内規程との突き合わせ(行53、行59)。

**骨組み**(確かめたあとに出す稟議書)

1. 申請内容
2. 確かめた結果
3. 費用対効果
4. 試験で確かめること
5. 判断の基準
6. 費用
7. 決裁をお願いする事項

**答える問い**:S1、S2、L3

**元の決裁事項が倒れる問い**

- S1(行20、行25、行29):費用に見合うのは1件あたり約39分以上減った場合なので、部全体の平均作成時間が約39分を下回れば、作成時間がすべてなくなっても届かず、行86 を頼む理由が立たない。約39分は全件で使う場合の値で、税抜なら約43分
- S2(行53、行59):社内規程に合わなければ導入しないので、行86 の承認は使われない
- S3(行29、行41、行73):全件で使う前提の試算なので、同意の割合が下がれば線はさらに上がる。文書の数字で計算すると、1件60分がすべてなくなる場合でも、利用率が約65%を下回れば届かない。ただし、書き手も同意の割合が分からず、顧客に聞いたことがないので、この問いは案1でも答えが出ない

**この案を選ぶなら先に見る問い**:部全体の平均作成時間(S1、行25)と、データの扱いが社内規程に合うか(S2、行53)。

**弱点**:データの扱いの確認が経営会議の前に終わるかは、書き手にも分からない。測定で分かるのは今の作成時間だけで、ツールでどれだけ減るかは分からない。開始は【2026年12月】(行14)より遅れうる。

## 案2 2つの問いに答える試験の稟議(本文に使った案)

**主張**:判断の中心は、作成時間の削減が費用に見合うかと、情報管理上の問題がないかの2つで(行66)、どちらもまだ答えが出ていない。この2つを確かめ、結果で本導入・規模縮小・中止を判断する。

**骨組み**

1. 申請内容
2. 背景と課題
3. 試験で確かめること(3.1 費用対効果、3.2 情報管理)
4. 判断の基準
5. 費用
6. 決裁をお願いする事項
7. 付録(測定の進め方と指標、費用対効果の計算、リスクと対策、実施体制とスケジュール、導入するツール、金額にしにくい効果)

**答える問い**:L1、L21、S7。問いごとに、今分かっていること、測り方、目安を1か所に集める。指標と判断の基準の対応が読める形になり、利用率の空欄や目安の未決がどの判断に関わるかも見える。リスクの表は付録に回し、判断に要る行だけ3章に入れる。

**弱点**:「参考値で見合わないのに、なぜ今試すのか」(S1〜S3)には答えられない。文書にそれを支える論拠がないので、枠を替えても閉じない。中間評価(L4)、ライセンス数(L9)、目安の30分と約39分(L5)の未決も残る。

**骨組み**

2. 支出の上限
3. 止める場面と基準
4. 期待する効果
5. リスクと対策
6. 決裁をお願いする事項

**答える問い**:L3、L12、S7、反論2

**弱点**:行62 の解約の事実は「費用が想定を超える」リスクの対策として書かれたもので、試験導入の根拠としては書かれていない。これを「だから試せる」につなぐと、書き手が言っていない根拠を足すことになる。3か月目に止められるかも、経営会議で判断するかが確認中で(行61)、背骨の一か所が未決のまま残る。

## 案2を選んだ理由

3つの理由で選びました。

- 背骨になる2つの問いは、行66 に書き手自身の文としてある。部全体の効果を試験で確かめることも行31 にあり、新しい根拠を足さずに組める
- 行16 の「効果と情報管理の状況を測定する」と、行80〜82 の判断の基準が同じ軸でそろう。今の doc-review.md は、効果を3章、情報管理を5章、測り方を6章に分けていて、1つの問いを読むのに3か所を行き来する
- 案3は読み手に通りやすいが、解約の事実を結論の根拠につなぐ点で、組み直しの範囲を超える
