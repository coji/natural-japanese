# 構成案(doc-review.md)

材料は doc-review.md の事実と頼む中身に限る。L と S の番号は report-logic.md と report-somosomo.md の指摘の番号。この2つの報告は修正前の doc.md を検査したものなので、行番号は doc-review.md の行に読み替えて書いた。doc-review.md で答えが出ている問い(L1、L3、L4、L9、S1、S2 の多く)は、案の材料から外している。

doc-review.md の背骨は「概要のあと、経緯→原因→影響→再発防止策と時系列で報告する」形である。決裁事項は2つあるのに、本文に置き場があるのは再発防止の方向だけで、調査に1週間かける判断は行8にしか出てこない。

## 案1 頼む中身を小さくする案:調査の1週間だけを頼む

- **主張**:メモリが上限に達した原因は確定していないので、まず改修が原因かどうかの調査に1週間かけてよいかを決めてほしい。再発防止の方向は、調査の結果と一緒に改めて出す。
- **骨組み**:概要/影響/原因/調査のあとで出すもの/付録A 経緯
- **答える問い**:L2、L8、L14、S3、S5、反論2
- **元の決裁事項が倒れる問い**:S3(行31、行43〜45、行47)の答えで改修が原因でないと分かれば、レビュー体制の強化は今回の障害と結びつかなくなる。L2(行45)のとおり、この方向と障害の関係は本文が「判断できない」と書いている。S5(行39、行47)のとおり、確認の結果で中身が変わるなら、確認の前に3つの方向を了承してもらう理由が薄い。
- **縮めた決裁事項**:受注検索の改修が障害の原因かどうかの調査に1週間かけてよいか
- **弱点**:部長の了承が2回になる。監視のしきい値の見直しも、調査の結果を待つことになる。
- **この案を選ぶなら先に見る問い**:S3(前日までに改修のほかに変わったものはあるか、半年前の通知と今回は同じ現象か)

## 案2 2つの判断に節を1つずつ対応させる(選んだ案)

- **主張**:障害は復旧したが、メモリが上限に達した原因は確定していない。判断は2つで、原因の節で調査の1週間を、再発防止策の節で3つの方向を決めてほしい。具体的な内容、担当、期限は調査の結果が出てから出す。
- **骨組み**:概要/影響/原因と調査/再発防止策/付録A 経緯
- **答える問い**:L2、L14、L16、S5、反論2
- **答え方**:調査の依頼に、疑う根拠と半年前の通知を並べる節を与える。L14 の「調査と対策が同列」は、調査の依頼を再発防止策の節の外に出すことで答える。L16 の時間は、どの判断の材料にもなっていないので付録に回す。
- **弱点**:調査と「改修のメモリ使用量の確認」が同じものかを文書から言い切れない(L14)。調査は原因の節、確認は再発防止策の表に分かれるので、別のものに読まれるおそれがある。

時系列の枠を捨て、経緯は付録に回す。影響は、調査に1週間かけるかを量る材料になるので、原因の前に置く。

## 案3 確定したことと確定していないことで分ける

- **主張**:確定しているのは、応答が止まり、再起動のあとに復旧し、10月28日の時点で再発がないことまでである。確定していないことがあるので、2つを決めてほしい。
- **骨組み**:概要/確定していること/確定していないこと/再発防止策/付録A 経緯
- **答える問い**:L1、L4、L12、L13、S5
- **弱点**:文を2つに仕分けるのは書き手の判断になる。「直接の原因」は「見ています」の形で、約40件の失敗が障害によることも本文にない前提で(L13)、どちらに置いても確信の度合いを動かしてしまう。影響の節もなくなる。

## 選んだ案と理由

案2を選ぶ。頼む中身を保つ案のうち、この案だけが、本文に置き場のなかった調査の判断に答える。案3は文の確信の度合いを動かすおそれがあり、この工程で保つべき「事実」に触れる。案1は決裁事項が変わるので、書き手にしか選べない。

見出しには、概要、経緯、原因、影響、再発防止策の語を残した。brief.txt の依頼がこの5つを入れるよう求めているためで、順序と枠だけを替えている。
