# 確認事項(doc-redesign.md)

**頼む中身を小さくする案**:今回決めてもらうのを「調査に1週間かけてよいか」の1点に絞り、再発防止の3つの方向の了承は調査の結果が出てから改めて頼む。改修が原因でないと分かれば、レビュー体制の強化は今回の障害と結びつかなくなるため。本文は頼む中身を保ったまま組み直してあり、選ぶのは書き手。

## 先に答える問い

1. 2つの判断は、情報システム部長と営業本部長のどちらに求めるものか。本文は宛先の2人に向けた形のまま書いている。
2. 前日までに、受注検索の改修のほかに変わったものはあるか。半年前の通知と今回は同じ現象と言えるか。分からないままだと、改修を疑う「時期が近い」という根拠が確かめられない。
3. 再起動後に1時間ごとに見ているメモリ使用量の具体的な値は、どこで確かめられるか。改修を本番に残したまま、同じ障害が起きないと言える材料はあるか。本文は「10月28日の時点で再発はありません」までしか書いていない。

## そのほか

判断の頼み方について

- 文書の作成日や報告日はいつか。本文には日付がなく、「確定していません」「確認中」がいつの時点の話か、読み手に分からない。
- 「改修が原因かどうかの調査」と、再発防止の1つ目「改修のメモリ使用量の確認」は同じものか。本文は、この2つの関係を言い切っていない。
- 調査の1週間は、いつから数えるのか。誰が調査するのか。
- 確認の結果で中身が変わるなら、確認の前に3つの方向を読み手に示す意味は何か。
- 調査が終わる前に同じ障害が起きたらどうするのか。調査しても原因が分からなかったら、どの時点で何を決めるのか。
- 障害の発生から報告までの間に、手元の記録で確かめられたことはどれか。確かめられるのに未着手のものはあるか。確認に使える記録はいつの分まで残っているか。確認に要る手間はどのくらいか。

原因について

- メモリの上限到達が応答の停止を起こしたことと、再起動が復旧をもたらしたことは、順番のほかに何で確かめたのか。再起動から復旧までに約45分ある。本文は「見ています」の形にした。
- 何がどうなっていれば改修を原因と判断し、どうなっていれば原因ではないと判断するのか。改修がメモリの使用量を増やしたと確かめられれば、上限到達の原因と言えるのか。
- 反映の前後のメモリ使用量の記録は残っているか。
- 改修が原因でないと分かったら、次に何を疑うのか。そのとき、監視のしきい値の見直しとレビュー体制の強化は残るのか。

再発防止の3つの方向について

- レビューの体制が障害につながったか判断できないのに、レビュー体制の強化を再発防止の方向に挙げる理由は何か。
- レビューが1人だったのは今回だけか、ふだんからか。1人では足りないと言える理由は何か。
- 今の監視のしきい値のどこに問題があったと考えているのか。調べた時点でメモリはすでに上限に達していたが、見直すと何が防げるのか。
- 改修の確認の結果で、監視のしきい値の見直しの中身はどの結果でどう変わるのか。
- 3つのほかに、改修を元に戻す案、原因が分かるまで何もしない案、止まってから戻るまでの時間に向ける案は検討したか。比べたのなら、その記録は文書に出せるか。改修を元に戻すと業務にどんな影響があるか。
- 3つの方向は、それぞれ誰がやり、誰が確かめるのか。レビュー体制は運用チームが変えられるものか。受注検索の改修を作った人とレビューした人はどの部署で、この報告を知っているか。
- 3つの方向は原因に応じて考えた策というより、原因が未確定という報告に策の形を添えたものだ、という反論にどう答えるか。今の時点で言えるのは「調査中」までではないか。

時間の扱いについて

- 通知から再起動までの50分と、再起動から復旧までの約45分を、長いと見ているのか、問題ないと見ているのか。内訳は分かるか。本文では付録に置いた。本当の問題は止まっていた時間のほうだ、という反論にどう答えるか。
- 「1時間半ほど」は、通知の 10:15 を止まり始めとして数えた長さか。止まり始めの時刻は何から確かめたのか。

影響について

- 止まり方は全面的だったのか断続的だったのか。「1時間半ほど応答しなくなりました」は、確認が終わったあとも同じ言い方で書けるか。
- 注文を入力するのは営業か顧客か。元の文書は「営業が入力した注文」を顧客が再入力する形になっている。本文では確認中と書いた。
- 「この時間帯」はいつからいつまでか。約40件の失敗が今回の障害によるものだというのは、確かめた事実か、時間帯が重なることからの推論か。
- 約260件は、入力された注文を確かめた結果か、約300件から約40件を引いた値か。
- 約40件は入力し直されたのか。処理の遅れはなかったか。
- 影響は営業の入力だけか。Web 画面を使う入力以外の業務や、営業以外の人への影響はないか。画面が止まっている間に入力を見送った注文は数えているか。
- 約300件と約40件は、誰がどこから数えた数字か。運用チームの外の人が確かめた部分はあるか。
