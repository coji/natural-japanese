# doc.md の somosomo 検査

## 文書の性格

10月21日の受注管理システムの障害を、情報システム部長と営業本部長に報告する文書です。

## 主結論

障害は再起動のあとに復旧したが、メモリが上限に達した原因は未確定で、再発防止策は3つを考えている段階だ、という報告です。

## 決裁者の論点

原因が確定しないまま改修を本番に置いている状態で、再発防止をこの進め方で進めてよいか。本文に決裁事項がないため、読み手がこの報告を読んで判断することとして立てました。

## 決裁事項を倒しうる問い

- S1 疑っている受注検索の改修は、いま本番で動いたままですか、元に戻しましたか。再起動のあと、メモリの使用量はどう動いていますか。
  - 倒れる場所:行12、行29、行41
  - 要る材料:改修の本番での状態と、再起動後のメモリ使用量の記録
  - どう倒れるか:改修が本番にあるままメモリが増え続けているなら、「検討中」のまま読み手に渡す報告は成り立ちません
- S2 入力に失敗した約40件は、全件が入力し直されたことを確かめましたか。入力するのは営業と顧客のどちらですか。
  - 倒れる場所:行10、行35
  - 要る材料:約40件のその後の記録と、納期への影響を確かめた先
  - どう倒れるか:入力し直されていない注文が残っていれば、影響の報告が過去形で書けず、営業本部長に先に頼むことが出てきます
- S3 この報告で2人に何を決めてほしいのですか。「再発防止策の中身は、改修のメモリ使用量を確かめてから決める」という進め方の了承ですか。ほかに決めてもらうことはありますか。
  - 倒れる場所:行12、行41、行49
  - 要る材料:読み手それぞれに求めることと、調査にかかる期間と体制
  - どう倒れるか:求めることが分からなければ、読み手は読んで終わりになり、3つの策はどれも動きません

## 前提

- S4 改修のほかに、同じ時期に本番で変わったものはありませんか。本文の根拠は時期が近いことだけです。
  - 倒れる場所:行12、行29、行45
  - 要る材料:同じ時期の本番の変更記録
- S5 再起動から復旧まで約45分かかっています。再起動で直ったと言えますか。
  - 倒れる場所:行8、行23、行27
  - 要る材料:再起動のあとの応答とメモリ使用量の時刻ごとの記録

## 問いそのもの

- S6 反映の前後でメモリ使用量がどう動いたかは、監視の記録で手元から確かめられませんか。確かめてから出せることを、出してから確かめる形になっていませんか。
  - 倒れる場所:行12、行29、行45
  - 要る材料:反映の前後の監視の記録

## 他の選択肢

- S7 「元に戻す」ことと比べましたか。本文の比べた案は「なし」です。比べたなら、何を軸に比べ、その記録は文書に出せますか。
  - 倒れる場所:行41、行45
  - 要る材料:元に戻す案と残す案を比べた記録

## 覆る条件

- S8 改修が原因でなかったとき、3つの策のどれが残りますか。行49は「中身も変わることがあります」としか書いていません。
  - 倒れる場所:行45〜49
  - 要る材料:原因ごとにどの策を残すかの書き手の考え
- S9 過去に同じサーバーで、同じ通知が出たことはありますか。あれば今回を改修のせいとは読めなくなります。
  - 倒れる場所:行12、行29
  - 要る材料:過去の監視の通知の記録
- S10 止まり方が全面的か断続的かで、影響の大きさの読みは変わりますか。
  - 倒れる場所:行8、行35、行37
  - 要る材料:入力の成功と失敗の時刻が分かる記録

## 利害と実行

- S11 通知から再起動までの50分と、再起動から復旧までの約45分は、何にかかった時間ですか。3つの策はどちらの時間も扱っていません。
  - 倒れる場所:行23、行45〜47
  - 要る材料:その間の対応の記録
- S12 3つの策は、誰がやる想定ですか。レビュー体制を決める人は、この文書の宛先の中にいますか。
  - 倒れる場所:行41、行47
  - 要る材料:策ごとに決める人と実行する人
- S13 「顧客からの問い合わせはありませんでした」は、顧客への影響の物差しになりますか。手間をかけた顧客への対応は決まっていますか。
  - 倒れる場所:行10、行35
  - 要る材料:約40件の顧客への対応の記録

## 反論(仮の立場)

- 行29は根拠が時期の近さだけだと認めています。その一方で行45〜47の3つの策はどれも改修と今回の通知に結びついていて、原因が改修だという見立てに沿って並べただけだ、という読みが成り立ちます。
