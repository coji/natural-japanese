# doc.md の確認事項

## 先に答える問い

1. 改修を切り戻さずに本番に残している理由は、本文にありません。決裁者に聞かれたら、どう答えますか。調査が終わる11月5日までに再発したときの扱いは決まっていますか。
2. 改修を疑う根拠は「反映と障害の時期が近いことだけ」と書いています。反映の前後でメモリ使用量がどう動いたかと、同じ時期に本番で変わったものがほかにないかは、手元の監視の記録と変更の記録で分かりますか。
3. 聞いて分からなかったことが2つあります。この注文をふだん入力するのは営業と顧客のどちらか、入力の成功と失敗の時刻ごとの内訳はどうかです。どちらも今回の2つの決めごとを左右しないので、本文は書き手の答えの範囲で書きました。報告の相手から聞かれたら答えられますか。

## そのほか

- 再起動から復旧までに約45分かかった理由は何ですか。本文は、メモリの上限到達を「直接の原因と見ている」と書いていますが、再起動のあとすぐには直っていません。
- 通知から再起動までの50分は、何にかかった時間ですか。再発防止の3つの方向は、この時間も再起動のあとの約45分も扱っていません。
- 改修が原因でなかったとき、3つの方向のどれが残りますか。本文は「ほかの2つの策の中身も変わることがあります」としか書いていません。
- 原因が分かる前に「レビュー体制の強化」の方向を了承してもらう理由は何ですか。本文は、体制が障害につながったかは判断できないと書いています。
- 監視のしきい値を見直すと、今回の何が防げますか。本文に書いてあるのは、10:15 の通知がきっかけだったという事実だけです。
- ふだんのレビューは何人で行っていますか。今回の1人がふだんの運用なのか例外なのかで、「強化」の意味が変わります。
- 改修を元に戻す案と残す案を比べた記録はありますか。
- 3つの方向のうち、レビュー体制を決める人は宛先の中にいますか。実行する人は誰を想定していますか。
- 過去に同じサーバーで、同じ通知が出たことはありますか。
- 調査の開始日は10月29日ですが、了承が必要な期限が本文にありません。この報告を出す日と、いつまでに了承が要るかを書くかどうかを決めてください。報告書には作成日もありません。
- 入力の失敗のほかに、検索や参照など、受注管理システムのほかの業務への影響はありましたか。
- 「顧客からの問い合わせはありませんでした」は、顧客への影響の物差しになりますか。聞き直しの手間をかけた顧客への対応は決まっていますか。
- 3つの方向の並びは、調査、検知、開発の工程と切り口がそろっていません。「改修のメモリ使用量の確認」は調査そのものなので、決めごとの2つが重なっています。このまま並べますか。
