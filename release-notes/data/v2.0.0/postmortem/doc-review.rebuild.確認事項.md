# 確認事項(doc-review.rebuild.md)

**頼む中身を小さくする案**:今回決めてもらうのを「調査に1週間かけてよいか」の1点に絞り、再発防止の3つの方向の了承は調査の結果が出てから改めて頼む。改修が原因でないと分かれば、レビュー体制の強化は今回の障害と結びつかなくなるため。この案を選ぶなら、先に下の問い2の答えを見る。本文は頼む中身を保ったまま組み直してあり、選ぶのは書き手。

## 先に答える問い

1. 2つの判断は、情報システム部長と営業本部長のどちらに求めるものか。本文は宛先の2人に向けた形のまま書いている。
2. 前日までに、受注検索の改修のほかに変わったものはあるか。半年前の通知と今回は同じ現象と言えるか。分からないままだと、「時期が近い」という改修への疑いの根拠が確かめられない。
3. 再起動後に1時間ごとに見ているメモリ使用量の具体的な値は、どこで確かめられるか。本文は「10月28日の時点で再発はありません」までしか書いていない。改修を本番に残したまま、同じ障害が起きないと言える材料はあるか。調査の1週間のあいだ、改修を本番に残してよいと考える理由は何か。

## そのほか

判断の頼み方について

- 「改修が原因かどうかの調査」と、再発防止の1つ目「改修のメモリ使用量の確認」は同じものか。本文は調査の依頼を「原因と調査」の節に、確認を再発防止策の表に置いたが、2つの関係は言い切っていない。同じものなら、確認を再発防止策の表に残したまま了承を求めてよいか。別のものなら、調査では何を確かめるのか。
- 文書の作成日や報告日はいつか。本文には日付がなく、「確定しておらず」「確認中」がいつの時点の話か、読み手に分からない。10月28日の時点で、と書いたのは再発の有無だけである。
- 調査の1週間は、いつから数えるのか。誰が調査するのか。
- 確認の結果しだいで策の中身が変わるなら、確認の前に3つの方向の了承を求める意味は何か。
- 調査が終わる前に同じ障害が起きたらどうするのか。調査しても原因が分からなかったら、どの時点で何を決めるのか。
- 何がどうなっていれば改修を原因と判断し、どうなっていれば原因ではないと判断するのか。改修がメモリの使用量を増やしたと確かめられれば、上限到達の原因と言えるのか。
- 障害の発生から報告までの間に、手元の記録で確かめられたことはどれか。確かめられるのに未着手のものはあるか。確認に使える記録はいつの分まで残っているか。確認に要る手間はどのくらいか。

原因について

- メモリの上限到達が応答の停止を起こしたことと、再起動が復旧をもたらしたことは、順番のほかに何で確かめたのか。再起動から復旧までに約45分ある。本文は「見ています」の形のままにしている。
- 反映の前後のメモリ使用量の記録は残っているか。
- 改修が原因でないと分かったら、次に何を疑うのか。そのとき、監視のしきい値の見直しとレビュー体制の強化は残るのか。

再発防止の3つの方向について

- レビューの体制が障害につながったか判断できないのに、レビュー体制の強化を再発防止の方向として挙げる理由は何か。
- レビューが1人だったのは今回だけか、ふだんからか。1人では足りないと言える理由は何か。
- 今の監視のしきい値のどこに問題があったと考えているのか。調べた時点でメモリはすでに上限に達していたが、見直すと何が防げるのか。
- 改修の確認の結果で、監視のしきい値の見直しの中身はどう変わるのか。
- 表の右の列「今回の障害との関係」は何を書く欄か。1行目は確認の状況を、2行目と3行目は今回の出来事を書いている。それぞれの策が再発を防ぐ理由は、どの行にも書かれていない。
- 3つのほかに、改修を元に戻す案、原因が分かるまで何もしない案、止まってから戻るまでの時間を縮める案は検討したか。比べたのなら、その記録は文書に出せるか。改修を元に戻すと業務にどんな影響があるか。
- 3つの方向は、それぞれ誰がやり、誰が確かめるのか。レビュー体制は運用チームが変えられるものか。受注検索の改修を作った人とレビューした人はどの部署で、この報告を知っているか。
- 3つの方向は原因に応じて考えた策というより、原因が未確定という報告に策の形を添えたものだ、という反論にどう答えるか。今の時点で言えるのは「調査中」までではないか。

時間の扱いについて

- 通知から再起動までの50分と、再起動から復旧までの約45分を、長いと見ているのか、問題ないと見ているのか。50分と約45分の内訳は分かるか。本文では付録に置いた。本当の問題は止まっていた時間のほうだ、という反論にどう答えるか。
- 「1時間半ほど」は、通知の 10:15 を止まり始めとして数えた長さか。止まり始めの時刻は何から確かめたのか。

影響について

- 止まり方は全面的だったのか断続的だったのか。「1時間半ほど応答しなくなりました」は、確認が終わったあとも同じ言い方で書けるか。本文では、「応答しなくなりました」と「この間に入力できた注文もあり」を両方残し、概要に確認中と書いている。
- 再入力するのは営業か顧客か。本文は「顧客に再入力の手間をかけています」「営業が顧客に再入力を頼みました」と言い切りながら、同じ節に「入力し直すのが営業か顧客かは確認中」とも書いていて、この食い違いはそのまま残している。
- 「この時間帯」はいつからいつまでか。約40件の失敗が今回の障害によるものだというのは、確かめた事実か、時間帯が重なることからの推論か。
- 約260件は、入力された注文を確かめた結果か、約300件から約40件を引いた値か。
- 約40件は入力し直されたのか。処理の遅れはなかったか。
- 影響は営業の入力だけか。Web 画面を使う入力以外の業務や、営業以外の人への影響はないか。画面が止まっている間に入力を見送った注文は数えているか。
- 約300件と約40件は、誰がどこから数えた数字か。運用チームの外の人が確かめた部分はあるか。
