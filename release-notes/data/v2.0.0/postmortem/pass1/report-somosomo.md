# somosomo の検査報告:doc.md

## 文書の性格

10月21日の受注管理システム障害の経過、原因の調査状況、影響、検討中の再発防止策を、情報システム部長と営業本部長に報告する文書。

## 主結論

10月21日(火)の午前中、受注管理システムの Web 画面が1時間半ほど応答しなくなった。メモリが上限に達した原因はまだ確定していない。

## 決裁者の論点

原因が確定していないいま、同じ障害がまた起きない状態で受注業務を続けられているか。続けられているなら、再発防止策の検討をこのまま運用チームに任せてよいか。

## 決裁事項を倒しうる問い

### S1 いまも同じ障害が起きうる状態ではないか

- 問い:疑っている受注検索の改修は、いま本番で動いたままですか、元に戻しましたか。再起動のあと、メモリの使用量はどう動いていますか。
- 倒れる場所:行12、行29、行41。改修が原因で本番に残っているなら、「再発防止策は検討中」という報告は、再発を待つ状態の報告になる。
- どう倒れるか:読み手が最初に判断するのは今後の防止策ではなく、いまの業務を続けてよいかで、文書はそこに答えていない。
- 要る材料:改修の現在の状態が分かる記録、再起動後のメモリ使用量の推移。

### S2 約40件の注文は回復したのか

- 問い:行35 は再入力を「頼みました」までで、再入力が済んだとは書いていません。約40件は全件入力し直されたことを確かめましたか。約40件と約300件は、どの記録から数えた数ですか。
- 倒れる場所:行10、行35。「顧客からの問い合わせはありませんでした」が影響の小ささの根拠に読まれているが、回復が確かめられていなければ、受注の取りこぼしが残っている可能性がある。
- どう倒れるか:営業本部長が知りたいのは受注が落ちていないかで、未入力が残っていれば、この報告の影響の見積もりが成り立たなくなる。
- 要る材料:失敗した注文の一覧と、その再入力の完了の記録。件数の出どころが分かるログや集計。

### S3 宛先の2人は何を求められているのか

- 問い:この報告は、共有するためのものですか、判断してもらうためのものですか。判断なら、何を決めてほしいのかが本文のどこにも書かれていません。行41 の「担当、期限はまだ決まっていません」は、宛先の2人が決めることですか、運用チームが決めることですか。
- 倒れる場所:行3、行41、行49。誰が次を動かすのかが読み手に分からなければ、再発防止策の節は誰も動かさない一覧になる。
- どう倒れるか:読み手に求めることが「任せる」ではなく「決める」なら、いまの文書には判断の材料も頼む文も足りていない。
- 要る材料:この報告のあとの進め方と、宛先の2人に期待する役割についての書き手の判断。

## 前提

- S4 行29「疑っているのは前日の夕方に反映した受注検索の改修」:障害の前に入った変更や負荷の変化で、改修のほかに調べたものはありますか。調べていないなら、時期が近いのは改修だけという前提で書かれていることになります。
  - 倒れる場所:行12、行29、行45、行49。改修が無関係なら、再発防止策の3つとも足場を失う。
  - 要る材料:障害の前後の変更の記録、当日と通常日の処理量の比較。
- S5 行8「1時間半ほど」、行19「10:15」:営業の画面が実際に止まり始めたのは、通知より前ではありませんか。通知より前に止まっていたなら、それが監視のしきい値を問う材料になります。
  - 倒れる場所:行8、行46。
  - 要る材料:Web 画面の応答の記録、営業から最初に連絡があった時刻。
- S6 行37「確認中」:止まり方は、この報告を出す前に確かめられないことですか。確かめられるなら、確認中のまま部長に出す理由はありますか。
  - 倒れる場所:行8、行35、行37。
  - 要る材料:入力の成功と失敗の時刻が分かる記録。

## 問いそのもの

- S7 行29「まだ確かめていません」、行45:改修のメモリ使用量の確認は、再発防止策として提案する前に、手元の材料で済ませられることではありませんか。確かめてから出せることを、これからやる策に挙げる形になっていませんか。
  - 倒れる場所:行12、行41、行45、行49。
  - 要る材料:改修前後のメモリ使用量を比べられる記録があるかどうか。

## 他の選択肢

- S8 行41:`比べた案` は「なし」です。改修を元に戻す、何もしない、範囲を絞る、といった型と比べましたか。比べたなら記録は文書に出せますか。
  - 倒れる場所:行41、行43〜行47。
  - 要る材料:検討した案と、選ばなかった理由の記録。

## 覆る条件

- S9 行49「結果によっては」:改修のメモリ使用量が増えていなかった場合、次に何を調べますか。文書は改修が原因だった場合の筋しか見せていません。
  - 倒れる場所:行12、行29、行45、行49。
  - 要る材料:改修が原因でなかった場合の調査の方針。

## 利害と実行

- S10 行23、行43〜行47:通知から復旧まで95分かかりましたが、3つの策はどれも復旧までの時間を対象にしていません。同じことが起きたとき、また95分かかる見込みですか。
  - 倒れる場所:行23、行41、行43〜行47。
  - 要る材料:50分と45分の内訳が分かる当日の対応記録。
- S11 行4、行18、行47:改修を作り、レビューしたのは誰ですか。作成者の運用チームと同じ部門なら、レビュー体制の評価を当事者が行うことになり、別の部門なら、その部門が文書に出てきません。
  - 倒れる場所:行31、行47。
  - 要る材料:改修の担当とレビュー担当の所属。

## 反論(仮の立場)

行10・行35 の「顧客からの問い合わせはありませんでした」は、影響が小さかったことを示すのではなく、顧客が営業からの依頼に従っただけで、負担が表に出ていないとも読める。営業本部長の立場からは、件数よりも顧客に手間をかけたこと自体が重い、という読みが成り立つ。
