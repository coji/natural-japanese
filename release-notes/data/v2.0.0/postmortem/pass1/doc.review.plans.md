# 構成案:受注管理システム障害報告書

問いの番号は `report-logic.md`(L)と `report-somosomo.md`(S)のもの。行番号は `doc.md` の行。

## 案1 頼む中身を小さくする案

- 主張:まず、改修が原因かどうかの調査に1週間かけることだけを了承してほしい。再発防止の方向は、調査の結果と一緒に改めて頼む
- 骨組み:了承をお願いしたいこと / 確かめること / 影響 / 経緯 / 調査のあとで頼むこと
- 答える問い:L3、L8、S3、S4、S7、S9
- 元の決裁事項が倒れる問い:
  - S4(行12、行29、行45、行49):改修が無関係なら、3つの方向はどれも足場を失う
  - L3(行31、行47):レビューの体制が障害につながっていなければ、レビュー体制の強化を今回の策として頼む理由がなくなる
  - S7(行29、行45):改修前後のメモリ使用量を手元の記録で比べられるなら、調査の1週間も頼まずに済む
- 縮めた決裁事項:改修が原因かどうかの調査に1週間かけてよいか
- 弱点:書き手が2つ頼むと答えたのに、1つに縮める。選べるのは書き手だけで、答えで前提が崩れたわけでもない

## 案2 いまの状態を先に置く案(頼む中身を保つ)

- 主張:了承をお願いしたいのは2つで、その判断の前に、いま改修が本番に残っていて10月28日の時点で再発がないことを示す
- 骨組み:了承をお願いしたいこと / いまの状態 / 確かめること / 影響 / 再発防止策 / 経緯
- 答える問い:S1、S2、S3、L8
- 弱点:再発がないことを、調査を急がなくてよい理由と読まれるおそれがある。文書はそう結んでいないので、本文でも結ばない

## 案3 分かっていることと分かっていないことで分ける案(頼む中身を保つ)

- 主張:障害の事実と回復は確定している。原因が確定していないので、確かめる1週間と方向の了承を頼む
- 骨組み:了承をお願いしたいこと / 分かっていること / 分かっていないこと / 再発防止策 / 経緯
- 答える問い:L1、L4、L7、S2、S6
- 弱点:「分かっていないこと」が1つの節に集まるので、止まり方の確認中が目立ち、調べられることを調べていない文書に見える

## 選んだ案

案2を選んだ。頼む中身を保つ案のうち、読み手が最初に判断する「いまの業務を続けてよいか」(S1)に最初の2節で答えられるためである。案1は書き手にしか選べないので、本文にしていない。案1を選ぶなら、S4、S7、L3 の答えを先に見る。
