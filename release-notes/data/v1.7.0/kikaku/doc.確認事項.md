# 確認事項(doc-review.md)

## 先に答える問い

1. 2月の最終案で開始を見送る条件は何か。試行で何が起きたら「業務に支障が出た」と見るのか。2月の会議に「始めない」と決める余地を残すのか
2. 外勤の方などは、ふだん VPN を同時に何件使っているか(曜日や時間帯で一番多いとき)。在宅勤務者の36名と足して100件に収まるか
3. 自由記述で在宅勤務に触れた4名は、「柔軟性のなさ」を挙げた9名に含まれるか。残りの回答は勤務時間や休暇など、別の柔軟性を指していないか。アンケートの中で、この理由は何位だったか(元の文書では「上位」と書いていたが、本文からは外した)

## そのほか

- 職種別の離職率は内勤がおよそ11%(19/180)、内勤以外がおよそ17%(12/70)。離職が多いのは対象外の側に見えるが、対象外の職種向けの「別途検討」は、誰がいつまでに進めるのか
- 在宅勤務以外の打ち手(時差出勤、休暇の取りやすさなど)や、何もしない場合と比べたか。比べていないなら、その理由
- 採用で見劣りしているのは確かめた事実か。直近の応募数、内定承諾率、辞退の理由は手元にあるか。辞退の理由に在宅勤務は挙がっているか
- 週2日、曜日の自由選択、試行範囲を広げる案など、範囲の違う案と比べて今の形を選んだか。競合2社の条件(日数、曜日の決め方、承認の要否)と並べたか
- 上長が日を変えた場合、変更先の曜日にも割り当ての制約をかけるか。変更が続いて制度が使えなくなるのを防ぐ歯止めはあるか
- 部署の人数に差があると、曜日ごとの在宅勤務者に偏りが出ないか。部署別の内勤人数を曜日に割り振ると、一番多い曜日は何名か
- 30名の試行で測る接続数の最大値から、180名で始めたときの接続数をどう読むのか。外勤の方などの利用量を測るのが目的なら、そう書くか
- 試行は2月まで続く。2月の経営会議の時点で、試行の結果はどこまで出ている見込みか
- 試行期間中の扱い(暫定ルールの要否)は、1月の試行開始までに決まるのか
- PCの調達、届出、説明会のどれかが遅れたとき、4月開始を動かすのか、規模を縮めて始めるのか
- 10月の報告で、どの数字がどうなっていたら拡大・維持・縮小・取りやめを選ぶのか。半年の離職率を年間の数字とどう比べ、在宅勤務以外の要因とどう分けるのか
- 退職者1名あたりの採用・育成コスト(X 円)の集計はいつ出るか
- 導入前の基準値(応募数、内定承諾率、従業員アンケートの満足度)は取ってあるか
- 目的は2つ(離職の抑制、採用力の向上)だが、効果の表には「定着と満足度」が3つ目にある。これは目的に入れるか。「定着」は離職の抑制と同じものではないか
- 情報システム部は、11月〜12月の調整、利用状況の確認、運用ルールづくり、PCの手配を、この日程で引き受けているか
- 申請の承認、日の変更、在宅でできる業務の整理は上長の仕事になる。管理職に事前に聞き取りをしたか
- 対象者の「180名(試用期間中の者は除く)」は、除いたあとの人数か、除く前の人数か
- 試用期間中の者を除くことは、採用で在宅勤務制度を示すことと両立するか
- 「月曜や金曜に偏るおそれ」の出どころは何か
- 「育児や介護との両立がしやすくなる」の根拠はあるか
- 勤務場所の「カフェ等は認めない」は、実家やサテライトオフィスをどう扱うか
