入口

いりぐち【入口】

名
  1. 1中に入るための場所。出入りする所。建物の入口／入口で待つ。

注意技術文書で、英語の entry point を1語で訳して使うと、読み手には何のことか分からない。

公開エンドポイント

英語の直訳を、読み手にとって自然な用語に直します

natural-japanese は、AI に書かせた日本語を読みやすくする Agent Skill です。この版では、技術文書に混ざる「入口」(entry point)や「要求」(request)のような言葉を、「公開エンドポイント」「リクエスト」に直します。

変わったこと

  • 書くときも直すときも、仕上げに、読み手にとって自然な用語かを確かめます。
  • 「失効が効く」は「次のリクエストから通らなくなる」と、起きることを書きます。
  • 頼み方は変わりません。これまでどおり「読みやすくして」と頼めば行います。

確かめたこと

Opus に技術系の相談資料を書かせ、3回直しを頼みました。条件ごとに2本作り、どの条件か伏せて別のモデル(Fable)に、読み手にとって不自然な用語を挙げさせました。数字は1本目・2本目の件数で、少ないほどよい数字です。

スキルなしv1.6.0v1.7.0
インフラへの相談3件・7件4件・0件0件・0件
アナリストへの相談1件・1件0件・0件0件・0件

スキルなしは2題材とも、3回の直しのうち図を足す依頼で「公開の入口」と書きました。

苦手なこと

  • 「事実」「影響」「承認」のように、語は正しくても文脈で不自然になる言葉は、まだ見つけられません。
  • スキルを使うと時間がかかります。上の相談資料では、スキルなしが約60秒、v1.7.0 が150〜260秒でした。v1.6.0 との差は測っていません。

同じようなスキルを作っている方へ

書いたモデルは、自分の意図を知ったまま読み返すので、こうした言葉に気づけません。そこで、気づく役を外に出しました。

  • calques.py:「拾う」「効く」のように機械の処理に当てた動詞と、「入口」「〜先」のように仕組みを場所にたとえた名詞を、決めた一覧から候補として並べます。判断はしません。
  • 読み手役:書いた経緯を知らない別のエージェントに本文だけを渡し、決まった呼び名がある語と、英語を1語ずつ置き換えた語だけを挙げさせます。

左の17件のうち、calques.py だけで11件、読み手役を合わせて13件を見つけました。人が直したあとの版で、誤って挙げたのは数件です。書くときの原則・calques.py・読み手役のどれが効いたかは、切り分けていません。「確かめたこと」の判定役(Fable)には、人が直した例を基準として渡しています。

前の版より悪くなっていないか

v1.6.0 と同じ技術記事と PR の説明文10本を、Sonnet(effort high)に直させました。直すべき箇所と残すべき箇所は、作者があらかじめ決めておきました。1回ずつの結果で、差はぶれの範囲です。

直すべき23件のうち直した(多いほどよい)残すべき40件のうち手を入れた(少ないほどよい)
v1.6.011件12件
v1.7.012件10件

試して採らなかったもの

  • 語の組み合わせの珍しさや、同義語辞書と分野ごとの頻度から見つける方法。人が書いた技術記事で、見つけたい言葉より多くの誤検出が出ました。
  • 読み手役に「分かりにくい語をすべて」と広く聞く方法。人が直したあとの版でも、30行で57〜70件を挙げました。
