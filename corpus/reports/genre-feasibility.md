# 他ジャンルのコーパス構築の実現性(S10〜S12)

調査日: 2026-10-02〜03。robots.txt・規約ページ・フィード・サイトマップへの軽いリクエストで確かめた。大量取得はしていない。

## 1. 結論

| ジャンル | 判定 | 理由 |
|---|---|---|
| business | **取れる** | 府省の白書は年版で日付が決まり、H(令和3・4年版)と W(令和7・8年版)を同じ書名でそろえられる。利用条件は公共データ利用規約(PDL1.0)で、CC BY 4.0 と互換。本文のコミットもできる(出典の明記と、第三者の権利部分の除外が条件)。規模は数百〜数千節で、tech より一桁小さい |
| blog | **条件付きで取れる** | はてなブログは記事ごとに公開日と更新日が機械的に取れ、規約にクロールを禁じる条項はない。ただし発見経路がはてなブックマークの人気エントリーに偏るため、H(無作為)ではなく H'(選ばれた記事)に近くなる。一括の再保存で更新日が全記事そろって動くブログがあり、更新日だけで除外すると H を取りこぼす。本文はコミットできない |
| essay | **条件付きで取れる(H は数百本規模)** | note は記事ページに公開日と更新日があり、robots.txt も記事ページを禁じていない。ただし公式 API はなく、非公式 API(`/api/*`)は robots.txt で禁止。サイトマップは2026年分しかなく、H の発見ははてなブックマーク経由の数百本に限られる。青空文庫は古い文体で W がない。小説家になろうは本文の自動取得が規約で禁じられていて取れない |

ジャンル名の範囲に注意がいる。ここでの business は「白書」で、提案書・報告書・メールとは書き手も読者も違う。essay も、note の「#エッセイ」やはてなブログの身辺雑記で、随筆の一部にすぎない。lint の対象(仕事の文書全般)を代表するとは言えない。

## 2. 横断的な注意

### 2.1 政府標準利用規約 2.0 は改名・改正済み

依頼の前提にあった「政府標準利用規約 2.0」は、2024-07-05 に「公共データ利用規約(第1.0版)」(PDL1.0)へ改名・改正された。総務省・経済産業省・厚生労働省・e-Gov は、いずれもサイトの利用規約で PDL1.0 を挙げている。

- CC BY 4.0 との互換は、デジタル庁の解説 PDF に明記されている。「本利用ルールは、クリエイティブ・コモンズ・ライセンスの表示 4.0 国際ライセンス……と互換性があります。……利用者が CC BY に従って利用することを許諾します。」([e-Gov データポータル: 公共データ利用規約](https://data.e-gov.go.jp/data/dataset/pulic_data_license)、[解説 PDF](https://data.e-gov.go.jp/data/dataset/1b0f6169-383c-4678-8636-c346b0d127ed/resource/5ad45c81-7c7a-4824-83aa-38fa1b313577/download/20240705_resources_data_outline_07.pdf))
- 条件は2つ。出典を書くこと、編集・加工したらそのことを書くこと。
- 第三者の権利: 「第三者が著作権を有しているものについては……利用者の責任で、当該第三者から利用の許諾を得てください」「明確に第三者が権利を有している部分の特定・明示等を行っていないものもあります」(同 PDF の2)。白書は民間の調査や寄稿を引用するので、コミットする本文からは囲み記事・コラム・引用図表の説明を外す必要がある。外し方の基準は決めていない。

### 2.2 更新日の一括書き換え

tech(Qiita)では `updated_at` が 2022-11-30 以降なら H から外した。はてなブログで同じ規則を使うと問題が起きる。

- `staff.hatenablog.com` の2020年8月の記事6本は、サイトマップの `lastmod` も記事ページの JSON-LD `dateModified` も、すべて `2023-09-20T17:10:2x` だった。一括の再保存とみられる。
- 個人ブログ2つ(`p-shirokuma.hatenadiary.com`、`fujipon.hatenablog.com`)の2020年8月分は、`lastmod` が記事ごとに公開日と同じ日だった。

対策の案: ブログ単位で `dateModified` の最頻値を見て、多数の記事が同じ時刻に更新されていれば一括更新とみなし、その時刻は除外の根拠にしない。それでも本文が書き換わっていない保証はない。厳密にするなら、Common Crawl や Internet Archive の 2022-11-30 より前のスナップショットと照合する(4章の未確認を参照)。

note でも記事ページの JSON-LD に `dateModified` がある(sources.json の1本は公開 2018-04-17、更新 2023-07-15。H からは外れる)。一括更新があるかは未確認。

### 2.3 コミットの方針

PDL1.0 の白書だけが本文をコミットできる。ほかは現行の README の方針(本文は非コミット、URL と取得スクリプトをコミット)のままにする。はてなの規約第8条4項の「学術研究データとしての提供」は、はてながユーザーから受ける許諾で、第三者への許諾ではない。Developer Center の規約も「ユーザーが第三者に対し譲渡及び使用許諾をすることはできません」としている([はてな利用規約](https://policies.hatena.ne.jp/rule)、[API規約](https://developer.hatena.ne.jp/license))。

### 3.3 essay

| 経路 | 日付 | 規模 | 取得方法と規約 | 本文のコミット | 品質の指標 |
|---|---|---|---|---|---|
| **note** | 記事ページの JSON-LD に `datePublished` と `dateModified` | W: サイトマップは索引に11ファイル。確認した1ファイル(5万 URL)は全件 `lastmod` が2026年だった。`lastmod` は更新日なので公開日の古い記事も混ざり、W に入れるには `datePublished` で絞る必要がある。H: サイトマップにも、robots.txt で禁止された一覧ページ(`/*/archives`)にもない。はてブの人気エントリー経由で1日1本前後(2019・2022年)、4年分で数百本。ユーザーごとの RSS(`/{user}/rss`)は最新25件だけ | 公式 API はない。robots.txt は全 UA に `/api/*` を禁止しているので、よく使われる非公式 API は使えない。記事ページと `/*/rss` は禁止されていない。利用規約の禁止事項に自動取得の条項はなく、「当社のサービスの障害となる行為」の禁止と、「クリエイターの承諾があるものを除き、デジタルコンテンツを複製……する等、購読契約の範囲を超えて利用すること」の禁止がある。この条項が無料記事の解析用の複製に当たるかは未確認([note 利用規約](https://note.com/terms))。ヘルプ側のガイドラインは未確認 | できない | スキ数は記事 HTML になく(API は禁止)、未確認。はてブ数で代える。ジャンルの判定には `meta keywords` のハッシュタグが使える(「エッセイ」タグで絞る) |
| 青空文庫 | 底本の年で決まる。すべて H | 未確認 | robots.txt に一般の UA への制限なし。現行の README の方針でコミット済み | **できる**(パブリックドメイン) | なし |
| 小説家になろう「エッセイ〔その他〕」(ジャンル 9901) | API に `general_firstup`・`general_lastup`・`novelupdated_at` | メタデータは数万件規模(未確認) | 規約が「なろうデベロッパーで提供しているAPIを利用する以外の方法で、本サービスに自動化された手段を用いてアクセスしたり、データを収集したりすること」を禁止([規約](https://syosetu.com/site/rule/))。API は本文を返さない([技術マニュアル](https://dev.syosetu.com/man/api/))。API の利用目的は「研究機関での学術研究への寄与」などに限られ、小説家になろうの登録ユーザーしか使えない([なろうデベロッパー](https://dev.syosetu.com/))。**本文は取れない** | できない | `global_point`、`fav_novel_cnt` |

補足:

- 青空文庫は著作権の切れた作家の作品なので、文体が古く、W に当たるものがない。既存コーパスと同じく「古典的な随筆」の対照群にしか使えない。
- 小説家になろうは、投稿作品の AI 利用の申告を規約で求めている(申告と違う設定を禁止)。著者側の AI ラベルが付いた W は、調べた中ではここだけだった。API がこの申告を返すかは未確認。
- カクヨムには「エッセイ・ノンフィクション」のジャンルがあり、robots.txt は作品ページを許可している(`/works/*/episodes/*/read` を除く)。利用規約には「著作権法で認められた私的使用の範囲を超える複製、販売、出版のために利用することはできません」とある([カクヨム利用規約](https://kakuyomu.jp/legal/tos))。自動取得の条項は見当たらなかったが、私的使用を超える複製の禁止がコーパスの利用に当たるかは未確認。API はない。
- はてなブログの身辺雑記は、blog と同じ経路で essay の代わりになる。ジャンルの区別は、はてブのカテゴリ(暮らし・おもしろ)やブログのカテゴリで付けることになり、精度は未確認。

## 4. 最初の試走

### business: 情報通信白書の4年版

1. `https://www.soumu.go.jp/johotsusintokei/whitepaper/ja/{r03,r04,r07,r08}/index.html` から、節の HTML(例 `html/nb000000.html`)の一覧を取る。Shift_JIS で読む
2. 1秒に1リクエスト以下で節を取り、本文を抽出する。囲み記事・コラム・図表の説明は外す
3. 各ファイルに出典(書名・年版・URL・取得日)と「本文を抽出・加工して作成」を書く
4. `features.py` と lint を H(r03・r04)と W(r07・r08)にかけ、tech の F5・F6・F8 の向きが白書でも同じかを見る
5. 正誤表(`pdf/list_errata.pdf`)で W 版の改稿の範囲を確かめる

結果が tech と同じ向きなら、e-Gov の白書一覧から HTML 版のある白書を足していく。

### blog: はてなブログ 100ブログの試走

1. `b.hatena.ne.jp/hotentry/{all,life,fun}/{YYYYMMDD}` を、2019〜2022年8月と2026年8月の一部の日付について、5秒間隔で取る
2. はてなブログのドメイン(`hatenablog.com` `hatenablog.jp` `hatenadiary.com` `hatenadiary.jp` `hateblo.jp`)を抜き出す。独自ドメインのブログは記事 HTML の目印で判定する(方法は未確認)
3. 100ブログについて `sitemap_periodical.xml?year=Y&month=8` を取り、各年8月の記事 URL と `lastmod` を集める
4. 記事ページの JSON-LD で公開日と更新日を取り、ブログ単位で一括更新の時刻を検出してから H の条件をかける
5. 1ブログあたりの本数に上限(例: 年5本)を置き、件数取得 API ではてブ数を付ける
6. H として残った割合と、一括更新があったブログの割合を記録する。これで本格収集の規模を見積もる

### essay: note 200本の試走

blog の手順1の結果から `note.com/*/n/*` の URL を200本集め、`dateModified` で H として残る割合と、「エッセイ」タグの付く割合を測る。H で数百本しか残らないなら、essay は H' 相当の小さな層として扱い、無作為抽出の FP 基準は作らない。
