# 生成AI以前の、説明的・実務的な日本語 Web 文章の一覧

日本語の文章を直すスキルや道具を作る人が、「人間が書いた普通の文章に、誤って反応しないか」を測るための共通の基準データ。LLM-jp コーパス v4(国立情報学研究所 LLM-jp)から選んだ文書の一覧と、それを作り直す・取り出すスクリプトを置く。

本文は含めていない。各文書の著作権は書いた人にあり、LLM-jp コーパスのライセンス(ODC-BY・CC BY 4.0)はデータセットとしての許諾だからだ。利用者は `fetch_docs.py` で、LLM-jp コーパスの配布元から同じ文書を取り出す。

## 一覧

`manifest/explanatory-pre2022-v1.jsonl`(20,301件)。1行1文書で、次の項目を持つ。

| 項目 | 内容 |
|---|---|
| source | LLM-jp コーパス v4 の中のファイル |
| docId | LLM-jp コーパスの文書 ID |
| url | 元のページの URL |
| date | LLM-jp コーパスの収集日(書かれた日ではない。2022-10 以前なら、そのページは生成AI以前に存在した) |
| type | URL から推定した種類(行政・組織の発信・報道・ブログ・コラム・大学・その他) |
| sha256 | 本文の SHA-256(取り出した本文の照合に使う) |
| rule_version | 絞り込みの規則の版 |
| score | 「説明的・実務的な文章らしさ」の分類器のスコア(0〜1) |

## 作り方

1. **ファイルを時期で選ぶ**(`map_files.py`): ja_cc level0 は1ファイルがほぼ1回の収集に当たる。各ファイルの先頭だけを見て、主な収集年月を `file-map-level0.json` に記録した。v1 は 2017・2019・2021年の3ファイルから作った
2. **規則で絞る**(`build_subset.py`): 収集日が 2022-11-01 より前、通販・求人・不動産の一覧・Q&A・掲示板・スパムの多いドメインを除く、本文 800字以上で地の文の行が6割以上、同じ行の繰り返しが少ない
3. **LLM でラベルを付ける**(`label_sample.py`): 2,000件に、種類・使いやすさ(0〜3)・翻訳記事か・メニューの残骸・スパムを判定させた。モデルとプロンプトは `label_prompt.md`
4. **分類器で全件に広げる**(`train_classifier.py`): 「使いやすさ 2 以上で、翻訳記事でもスパムでもない」を正例として、文字 2〜4-gram のロジスティック回帰を学習した。評価データでの AUC は 0.87。閾値ごとの適合率と再現率は `classifier-report.md`
5. **一覧にする**: スコア 0.5 以上を残した。目的に合わせて `--min-score` で絞り直せる(0.7 以上で適合率は約0.9)

## 使い方

```bash
# 一覧から本文を取り出す(配布元から該当ファイルを流し読みする。1ファイルで数分かかる)
uv run corpus/llmjp/fetch_docs.py --manifest corpus/llmjp/manifest/explanatory-pre2022-v1.jsonl \
    --out docs.jsonl --min-score 0.7
```

## わかっている限界

- 種類は Web の文章に限られる。社内の議事録やメールは入っていない
- 分類器は LLM(gpt-6-luna)の判定をまねたもので、その判定の偏りを受け継ぐ
- 配布元から文書が削除されると取り出せなくなる(`fetch_docs.py` は飛ばして件数を報告する)
- 収集日は書かれた日ではない。古いページを後から収集したものも含まれる
